# XTrading 产品范围决策

更新时间：2026-08-20

## 1. 决策目的

本文把原迁移清单中的开放问题转成明确的当前版本边界。范围决策不等于伪造功能完成：已决定暂不建设的能力会从迁移验收中移出，涉及真实凭证、外部数据传输或真实资金的能力继续保持默认关闭，并列出独立验收条件。

## 2. 当前版本决策

| 议题 | 当前决策 | 当前版本交付 | 后续启动条件 |
| --- | --- | --- | --- |
| 用户自助注册、密码找回、新手引导 | 当前不开放 | 保留管理员创建用户、RBAC、登录与密码安全升级 | 产品转为公网多租户并完成邮件/短信、滥用防护和隐私评审 |
| 原生策略市场 | 当前不建设 | 提供用户私有策略、版本、复制、发布、回滚与激活 | 明确作者权益、审核、许可、收益分成和公开信息边界 |
| 原生量化数据中心 | 建设免费公共数据基线 | Binance/OKX 行情、Order Book、OI、资金费率、成交方向代理、风险雷达；Binance 实时清算采集 | 采购 NOFXOS/Coinank/Vergex 前需确认价格、SLA、再分发授权和降级策略 |
| NOFXOS | 可选增强，不作为运行依赖 | 能力矩阵明确可替代字段和限制；未配置时系统完整运行 | 提供正式合同、API Key、限频和字段授权后另行接入 |
| Hyperliquid | 当前版本不迁移 | 保留评估与威胁模型，不保存主钱包私钥 | 独立完成 Agent Wallet、Nonce、Builder Fee、撤销和资金风险评审 |
| X402 与链上支付 | 当前版本不迁移 | 与交易所账户访问彻底分离 | 出现明确支付业务、合规和链上结算需求后单独立项 |
| Backtest | 单独立项 | 当前仅提供真实历史数据持久化、分析和模拟策略运行 | 先确定撮合模型、手续费/滑点、数据版本、可复现实验协议和算力预算 |

## 3. 外部验收门槛

以下不是代码缺口，不能使用模拟结果冒充完成：

1. 真实 AI Provider：用户选择一个已配置模型，并明确允许发送合成测试 Prompt；验收响应、耗时、Token、费用与错误脱敏。
2. Binance、OKX、Bybit 大账户历史数据：使用用户提供的只读凭证，核对分页记录数、时间窗口、游标、重复率和完整性告警。
3. Telegram 自动回复：用户明确允许向绑定 Chat 发送资产、仓位、Trader、策略和诊断结果，且显式开启 `Trading.TelegramBot.Enabled`。
4. Telegram/Lark 自动通知：用户明确选择目标渠道和通知事件；发送失败必须记录，且不得改变交易状态。
5. 真实交易：必须另行完成 Provider 代码审查、测试网、限额、熔断、撤单与对账验收；当前构建不注册真实交易 Provider。

## 4. 安全默认值

- `Trading.Execution.Enabled=false`：禁止真实交易。
- `Trading.UserStream.Enabled=false`：私有账户 WebSocket 需显式开启。
- `Trading.TelegramBot.Enabled=false`：禁止默认轮询和外发。
- `Trading.MarketStream.Enabled=false`：公开清算采集按运维需要开启，不涉及账户凭证。
- Telegram 任务仅允许只读白名单命令，不允许下单、审批、删除、启动或配置修改。
- 清算热力图只显示实际落库数据；未启用采集或无事件时显示空状态，不生成模拟热力图。

## 5. 范围变更规则

任何将“当前不建设”改为“进入开发”的决定，都必须先更新本文和迁移清单，并补充数据授权、威胁模型、回滚方案、测试范围和验收负责人。仅增加前端入口或配置字段不能视为能力完成。
