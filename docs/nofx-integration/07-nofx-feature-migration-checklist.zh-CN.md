# NOFX 功能迁移清单

## 1. 文档目的

本文档用于持续跟踪 NOFX 功能向 XTrading 的迁移状态。状态以实际可运行链路为准，不以页面、表结构或按钮是否存在作为完成依据。

状态定义：

- `[x]` 已完成：实现、测试和最小验收均已完成。
- `[-]` 部分完成：已有模型、接口或页面，但业务闭环不完整。
- `[ ]` 未开始：目标项目中尚无有效实现。
- `[!]` 阻塞：依赖产品决策、外部凭证或高风险操作确认。

## 2. 当前结论

XTrading 当前已经具备管理后台、交易数据平台以及默认关闭的 AI 交易执行闭环。生产交易、自动通知和 Telegram 长轮询仍由独立服务端开关控制，默认均为关闭状态。

截至 2026-08-21 的复核结论：**迁移清单已无待开发条目，但外部验收尚未全部完成**。按第 3 至第 6 章状态条目机械统计，当前为 **111 已完成、4 部分完成、0 待做、1 阻塞**。本批在用户明确授权后补齐扩展市场上下文、Telegram 长轮询、Telegram/Lark 自动通知、审批链接、自动模式命令闭环，以及 Binance/OKX 测试网优先交易适配器。剩余 4 个部分项为 Binance/OKX/Bybit 真实大账户分页验收和 Telegram 账户数据回复边界；唯一阻塞项为本地没有已配置 AI 模型凭证，无法执行真实 Provider 请求。

已经稳定落地的主链路为：

`交易所凭证 -> 只读 Provider -> 资产/仓位/订单/成交同步 -> MySQL -> Dashboard/分析页面`

已落地但默认关闭的核心链路为：

`策略 -> 市场上下文 -> AI 模型 -> 结构化决策 -> 应用风控 -> 通知/审批 -> 下单 -> 成交对账 -> 收益归因`

- [x] 审批超时、防重复审批、原子状态迁移、操作人和命令关联审计。

验收标准：三种模式对同一信号产生不同且确定的行为；审批和自动模式的所有状态变化均可追踪。
